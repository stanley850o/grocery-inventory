Owner setup — email-code sign-in (one time, in Supabase)

How sign-in works: this app sends a 6-digit code to the email typed in, using Supabase Auth email codes. No social sign-in is used. Only the two household emails written into the app’s code are allowed — any other email gets an error and no code is sent.

If no code email arrives: in Supabase → Authentication → Email templates, check that email confirmation / the “Confirm email” template is on, and check the spam folder. The email comes from Supabase, not from this app.

Site URL: in Supabase → Authentication → URL Configuration, keep the Site URL set to this app’s address (e.g. your GitHub Pages URL) so any links in Supabase emails come back here. Email and password sign-in still works as a fallback below the code sign-in.

SQL schema — copy & run in Supabase 
create table if not exists public.inventory_items (
  id uuid primary key default gen_random_uuid(),
  barcode text unique not null,
  name text not null,
  brand text,
  image_url text,
  quantity integer not null default 0 check (quantity >= 0),
  location text not null default 'Pantry',
  created_at timestamptz default now(),
  updated_at timestamptz default now(),
  updated_by uuid references auth.users(id)
);
create table if not exists public.inventory_log (
  id bigint generated always as identity primary key,
  barcode text, item_name text, delta integer, mode text,
  user_id uuid references auth.users(id),
  created_at timestamptz default now()
);
alter table public.inventory_items enable row level security;
alter table public.inventory_log enable row level security;
-- Household policy: any signed-in user can read/write (tighten later if needed)
create policy "household read" on public.inventory_items for select to authenticated using (true);
create policy "household write" on public.inventory_items for all to authenticated using (true) with check (true);
create policy "log read" on public.inventory_log for select to authenticated using (true);
create policy "log write" on public.inventory_log for insert to authenticated with check (true);
How scanning works in the live version

Scan → barcode decoded on the phone → Open Food Facts lookup for name/photo → quantity ±1 saved to Supabase → anyone else signed in sees it when they connect or refresh. If Open Food Facts has no match, the first person types the name once; it’s saved against that barcode for everyone after that.

Built for the house — scan in at home, scan in at the store, scan out when you use it. Quantities are always editable.
